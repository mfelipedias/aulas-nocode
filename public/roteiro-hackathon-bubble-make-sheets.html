    Do zero ao sistema de inscrições do evento, com Bubble, Make e Google Sheets

    Este é o caminho completo, clique a clique, para construir a aplicação do Hackathon No-Code 2026. Uma pessoa preenche o formulário no Bubble, a inscrição fica salva no banco do Bubble, o Make copia os dados para uma planilha do Google e envia o e-mail de confirmação, e a organização acompanha tudo na planilha. Os nomes, os campos e a ordem são os mesmos das aulas.

    Cada etapa tem dois caminhos para o mesmo resultado: com a IA integrada (Bubble AI Agent e Maia, do Make), com o prompt pronto e o que conferir depois, e o passo a passo manual, que serve para fazer sem IA ou para corrigir o que ela errou.

      0.1A aplicação em uma frase

      Quando alguém clicar em "Quero minha vaga", crie uma inscrição com os dados do formulário, só se o e-mail estiver preenchido e ainda não existir. Depois, avise o Make, que grava uma linha na planilha da organização e envia o e-mail de confirmação.

      É a frase da Aula 2 ("quando [evento], faça [ação] com [dados], só se [condição]") somada à cadeia da Aula 3. As três ferramentas programam com a mesma gramática.

      0.2Arquitetura

      Por que a planilha não é o banco principal

      É a pergunta mais provável dos alunos. Dois motivos: (1) o Bubble precisa do dado para aplicar regras na hora, como bloquear e-mail duplicado, e consultar uma planilha a cada clique seria lento e gastaria créditos do Make; (2) a planilha é ótima para quem opera o evento: filtrar, exportar, imprimir a lista da porta, ligar o AppSheet. Cada ferramenta faz o que faz melhor.

      0.6O molde de todos os prompts

      Todos os prompts deste roteiro seguem o mesmo molde, com rótulos fixos. O molde é a frase da Aula 2 ("quando [evento], faça [ação] com [dados], só se [condição]") escrita por extenso, mais três linhas que protegem o app: onde mexer, o que não fazer e o pedido de plano. Quando o aluno reconhece os rótulos, ele lê o prompt como lê o workflow.

      ONDE: na página index.1 QUANDO: Botão Quero minha vaga is clicked.2 FAÇA: Create a new thing do tipo Inscricao. COM ESTES DADOS: nome = Input Nome's value; email = Input E-mail's value.3 SÓ SE: não existir Inscricao com o mesmo email.4 NÃO FAÇA: não altere outros elementos nem data types.5 ANTES DE APLICAR: descreva o workflow passo a passo e diga onde ficou a condição.6
      1ONDEUm recurso só por pedido: uma página, um data type, um workflow. Diz ao agente o contexto e limita o estrago.
      2QUANDOO evento, nos termos da ferramenta (is clicked, Custom webhook). É o gatilho da Aula 2.
      3FAÇA / COM ESTES DADOSA ação e os nomes exatos, sem acento, iguais nas quatro pontas. A IA não adivinha o nome que o workflow espera.
      4SÓ SEAs regras de negócio por extenso, e onde a condição fica (no evento, não no passo).
      5NÃO FAÇAO que não tocar. Agente bom ainda mexe em mais coisa do que você pediu.
      6ANTES DE APLICARObriga a IA a mostrar o plano e a explicar uma decisão. É aí que você pega o erro, e é aí que o aluno aprende.
      O sétimo prompt: "Sem alterar nada, explique…"

      Cada etapa termina com um prompt tracejado, que não constrói nada: pede à IA que explique o que acabou de fazer, nos termos da aula. Use-o em sala depois de conferir no lugar da verdade. A pergunta certa não é "funcionou?", é "por que está assim?". Exemplo: Sem alterar nada: explique por que a condição do workflow fica no evento e não no passo 1.

      A IA faz bem

      • Criar estrutura repetitiva: campos, elementos, módulos
      • Montar workflows e cenários a partir de uma descrição clara
      • Explicar um erro e propor a correção
      • Gerar dados fictícios coerentes

      Continua com você

      • Autorizar contas (conexões do Google, plugins)
      • Rodar, inicializar e ativar: Initialize call, Run once, ligar o cenário
      • Conferir as privacy rules que o agente cria por conta própria
      • Provar no lugar da verdade que funcionou
      Trabalhe numa cópia

      Antes de um prompt grande, faça uma cópia do app no Bubble (na Aula 2, o agente roda no app irmão hackathon-agente) e exporte o cenário do Make como blueprint. Se a IA fizer algo inesperado, você volta em segundos.

      1.2Convenções que evitam 80% dos erros

      Nomes sem acento e sem espaço

      Data types, campos, colunas da planilha e chaves do JSON: Inscricao, telefone, data_hora. Acento só no que é exibido (por exemplo, a opção "Automação" do option set). O Make e o AppSheet usam o cabeçalho da planilha como nome de campo.

      Mesmo nome em todo lugar

      O campo email se chama email no Bubble, no JSON, no Make e na planilha. Quando o nome é igual nas quatro pontas, o mapeamento fica óbvio e o erro aparece logo.

      E-mails de teste com plus addressing

      <email-da-aula>+ana@gmail.com chega na caixa da aula. Cada pessoa fictícia tem um e-mail único (o que testa a regra de duplicidade) e nenhum terceiro recebe nada.

      Renomeie cada elemento no Bubble

      "Input Nome", "Input E-mail", "Botão Quero minha vaga". Sem isso, o workflow mostra "Input A", "Input B", e é fácil ligar o campo errado (o bug número 1 da Aula 2).

      2.2Modelo de dados no Bubble

      Decisões que valem uma pausa na aula
      • Telefone é text, não number. Ninguém faz conta com telefone, e número perde o zero à esquerda, os parênteses e o hífen.
      • Trilha é option set, não data type. É uma lista fixa que só o desenvolvedor muda. Como data type, viraria tabela no banco e, em tese, usuários poderiam criar trilhas.
      • Data da inscrição não é um campo. O Created Date vem de graça.
      • O nome do data type é singular. Inscricao é uma inscrição; a lista é "All Inscricaos" (o Bubble pluraliza em inglês).

      A.3Glossário de bolso

      Data type Bubble

      Uma tabela do banco. Cada registro é uma thing.

      Option set Bubble

      Lista fixa definida pelo desenvolvedor. Não ocupa o banco.

      Only when Bubble

      Condição que decide se um evento ou passo roda. É lógica.

      API Connector Bubble

      Plugin para o Bubble chamar APIs externas, como o webhook do Make.

      Webhook Make

      API ao contrário: um endereço seu, esperando ser avisado.

      Filtro Make

      Condição na ligação entre módulos. O if do fluxo.

      Crédito Make

      Unidade de cobrança. Cada módulo executado custa um.

      JSON geral

      Pares de chave e valor entre chaves. A língua que os três sistemas falam.
